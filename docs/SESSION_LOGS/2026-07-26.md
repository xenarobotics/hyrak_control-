### Architectural analysis

Mapped every browser-reachable video transport (WebRTC, MSE, HLS/DASH,
WebCodecs) with latency figures, and the hard sandbox limits (no raw UDP, no
RTSP, ever). Established that **QUIC/HTTP3 is used nowhere** in the stack —
verified by grep for `aioquic`/`hypercorn`/`h3` and by reading
`frontend/src/lib/socket.ts:12` (socket.io pinned to `websocket`) and
`backend/app/main.py` (uvicorn HTTP/1.1).

Key reframe: WebRTC is not the quality/CPU problem — **re-encoding is**. The
reason re-encoding was unavoidable: **Chromium refuses H.265 in WebRTC SDP
negotiation**, so passthrough-to-browser is impossible with an H.265 air unit.

Produced per-option latency budgets and a per-scenario mode matrix.

### Bug 1 — air-unit video Start failure (FIXED, desktop 0.1.3)

Reproduced with a synthetic H.265 RTP stream on 5600 using the bridge's exact
arguments. Root cause: compile-time `-hwaccels` check + no `-vaapi_device`, so
ffmpeg auto-initialised `/dev/dri/renderD128` = firmware-disabled RTX 4070.
`renderD129` = AMD iGPU works. See ADR-005.

Ruled out by inspection: v4l2loopback loaded, `/dev/video10` present with
`user:japesh:rw-` ACL, `exclusive_caps=Y`, nothing bound to 5600. **The 0.1.2
stale-port theory was wrong.**

### Bug 2 — SITL connect hangs (FIXES SHIPPED, root cause unconfirmed, 0.1.4)

Found and fixed three separate defects:

1. `udpBridge.ts` bound `127.0.0.1` — verified experimentally that this drops
   all non-loopback packets, breaking SITL in WSL2/Docker/VM (WSL2 localhost
   forwarding is TCP-only). Now `0.0.0.0`. See ADR-006.
2. The generic `error` socket event had **no frontend listener**, and
   exceptions in the connect handler were swallowed by socket.io — either
   leaves the UI on "connecting" forever, the literal symptom. See ADR-007.
3. "Bound but silent" was invisible. Added a first-packet `receiving` status
   and an 8s SITL silence message naming the concrete causes.

Confirmed from `px4-rc.mavlink` that port 14540 and the push direction were
correct: `mavlink start -x -u 14580 -m onboard -o 14540`.

## Major discoveries

1. **`ffmpeg -hwaccels` reports compile-time support only.** Never a runtime
   capability check.
2. **DRM render node ordering matters.** `renderD128` = dead NVIDIA,
   `renderD129` = working AMD iGPU on the dev laptop. ffmpeg defaults to the
   first node.
3. **Chromium refuses H.265 in WebRTC negotiation** — the real reason the
   double transcode existed.
4. **`socket.bind(port, '127.0.0.1')` drops all non-loopback traffic** —
   verified, and fatal for WSL2 SITL.
5. **The server-sourced video path already exists** (`air_unit_udp`,
   `siyi_rtsp` in `signaling.py`) but binds `127.0.0.1` server-side, so it
   only works co-located — a dead end its own error string already documents.
6. **`signaling.py:152` blocks client overlays for server-sourced feeds** only
   because there's no local preview. A local preview unlocks
   `return_video=False` for free.
7. **`MediaStreamTrackGenerator` is unnecessary** once SRT owns the uplink.
8. **SRT cannot traverse UDP-blocking networks**, which makes multi-mode
   mandatory rather than optional.
9. **Crowd management and plate tracking are implemented** (268 + 410 lines,
   both registered) — the plan file claiming "not started" is stale.
10. **Intel iGPUs are the best case for VAAPI**, not the worst — Quick Sync
    HEVC decode since Skylake. The client CPU budget is better than assumed.

## Lessons learned

1. **Reproduce before theorising.** The 0.1.2 port-race fix was a guess and
   was wrong; the 0.1.3 fix came from reproducing with a synthetic stream. The
   same discipline found the UDP bind bug.
2. **A capability flag is not a capability.**
3. **Silent success is worse than failure.** Both bugs shared a shape: an
   operation "succeeded" while delivering nothing. Every bind/open that can be
   silently useless needs a first-data signal.
4. **A non-terminal UI state needs a guaranteed terminal event.**
5. **Check whether a feature already exists.** The server-sourced video path
   and the crowd/plate modules were both already built.
